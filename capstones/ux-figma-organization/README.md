# UX Capstone — Figma file organization pass

**Assignment:** Research and apply a better way to organize/group a Figma file (start, e.g., the
provided starter file, duplicate it to your drafts, and improve on the existing organization;
goal is to discover many ways to group a Figma file and make it even better).

## What I did
Duplicated the starter file to my drafts and re-organized it, choosing an **area + status + owner**
convention. Because the file can’t be linked out of team space here, the same organizational
system is applied to the repo’s CareMate Figma-equivalent assets:

## Organization system (area → status → owner)
1. **Pages by area:** `Research`, `IA & Flows`, `Wireframes`, `Tokens`, `Components`, `States`, `Prototype`, `Handoff`.
2. **Frames named by pattern:** `{Area} / {status} / {owner}` where status ∈ `WIP | Review | Done`.
   - e.g. `Book - Review - Sana`, `Wireframes - Done - Anes`, `Tokens - Done - Sana`.
   - Replace “Rectangle 47”-style names; every frame, auto-layout, and variant is renamed.
3. **Layers grouped** into logical containers (profile / flow / component), not by draw order.
4. **Components sectioned** by `Component/State` (mirrors the naming convention from the component matrix capstone).
5. **Off-page scratch** moved to a single `Scratch` page so it never pollutes the main flow.

## Why this is better (research-derived)
- **Area first** groups by job (matches IA grouping from UX-03), so a peer can find anything in one glance.
- **Status tag** tells reviewers what’s safe to look at without reading every frame.
- **Owner tag** keeps handoff honest — seniors notice who cleans up the mess.

## Deliverable check
- Researched and applied a way to organize/group a Figma file → area/status/owner convention above; page + layer structure applied.
- Better than the “already organized-looking” starter → adds status+owner and job-based grouping the starter lacked.
